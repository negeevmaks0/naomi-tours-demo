# Naomi Tours — Demo

Демонстрационный сайт каталога групповых путешествий и Telegram-бот для заявок на конкретный тур. Закрытый прототип, не коммерческая платформа.

Путь пользователя: **каталог → страница тура → «Оставить заявку» → `https://t.me/<BOT_USERNAME>?start=<tour_code>` → бот показывает выбранный тур → тестовая заявка → запись в SQLite.**

Заявка — только запрос на рассмотрение. Она не является бронированием, не подтверждает наличие мест и не связана с оплатой.

## Стек
Python 3.10+ (проверено на 3.10.8), FastAPI + Jinja2, HTML/CSS без JS-фреймворков, SQLite через SQLAlchemy 2.x, aiogram 3, pytest.

## Структура
```text
app/
├── main.py              # фабрика FastAPI-приложения (create_app)
├── config.py            # настройки из .env
├── database.py          # SQLAlchemy engine/сессии
├── models/              # Tour, Application
├── routers/pages.py     # /, /tours (?sort=nearest|latest), /tours/{tour_code}, /how, /about, /health
├── services/            # туры и deep link, заявки, загрузка seed
├── bot/                 # aiogram-бот: handlers.py, texts.py, profile.py, __main__.py
├── export_static.py     # статическая копия сайта для GitHub Pages
├── templates/           # Jinja2-шаблоны
└── static/{css,images}/ # стили и исходные фото, извлечённые из скриншотов
data/seed_tours.json     # содержимое туров (источник для БД)
tests/                   # pytest
```

## Установка (Windows PowerShell)
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```
Затем заполните `.env` (см. ниже). Для сайта достаточно пустого `.env`; кнопка «Оставить заявку» станет активной, когда задан `BOT_USERNAME`.

**Если `pip` не найден внутри `.venv`** (на некоторых установках Python `python -m venv` создаёт окружение без pip — ошибка `No module named pip`), установите зависимости глобальным pip прямо в окружение:
```powershell
python -m pip --python .venv\Scripts\python.exe install -r requirements.txt
```

## Переменные окружения (`.env`)
| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | для бота | токен от @BotFather |
| `BOT_USERNAME` | для ссылок на сайте | имя бота без `@`; из него строится `https://t.me/<BOT_USERNAME>?start=<tour_code>` |
| `ADMIN_CHAT_ID` | нет | числовой ID чата для уведомлений о заявках; если пусто — заявки только сохраняются в SQLite |
| `SITE_BASE_URL` | для показа с телефона | адрес сайта для ссылок в сообщениях бота. Локальный адрес (`127.0.0.1`, `localhost`) открывается только на этом ПК — тогда бот ссылок не присылает |
| `SITE_BASE_PATH` | нет | префикс путей, если сайт открыт не из корня домена (GitHub Pages: `/<repo>`); локально пусто |
| `ORGANIZER_NAME`, `ORGANIZER_CONTACT` | нет | организатор на странице «О нас» и в подвале; без значений блок не показывается |
| `DATABASE_URL` | нет | по умолчанию `sqlite:///./data/naomi_tours_demo.db` (путь от корня проекта) |
| `DEMO_MODE` | нет | зарезервировано, по умолчанию `true` |

## Запуск сайта
```powershell
python -m uvicorn app.main:create_app --factory --port 8000
```
Откройте http://127.0.0.1:8000. При старте создаются таблицы и туры загружаются из `data/seed_tours.json` (upsert по `tour_code`, ID туров стабильны).

## Запуск бота (отдельный процесс)
```powershell
python -m app.bot
```
Без `BOT_TOKEN` бот завершится с понятным сообщением. Бот работает через long polling, сайт и бот запускаются независимо и делят одну SQLite-базу.

Сценарий бота:
- `/start` без параметра — сообщение, что туры выбирают на сайте, и ссылка на каталог;
- `/start <tour_code>` — карточка тура (название, даты, длительность, цена, маршрут) и кнопка «Оставить заявку»;
- неизвестный код или тур, который уже начался/завершился, — объяснение и ссылка на каталог;
- заявка: имя (кнопка с именем из Telegram или ввод вручную) → необязательный комментарий («Пропустить») → сводка → «Отправить»/«Отменить»; `/cancel` в любой момент;
- сохраняется: ID тура, имя, комментарий, Telegram user ID и username (если есть), время в UTC;
- уведомление в `ADMIN_CHAT_ID` отправляется только если он задан. Итоговое сообщение честное: «сохранена и отправлена организатору» — только если уведомление реально доставлено, иначе «Заявка №N сохранена».

## Профиль бота: имя, описание, команды
Имя, описания и команды хранятся в `app/bot/profile.py`.
```powershell
python -m app.bot.profile           # показать текущий профиль (ничего не меняет)
python -m app.bot.profile --apply   # записать имя «Naomi Tours», описания и команды /start, /cancel
```
То же вручную через [@BotFather](https://t.me/BotFather): `/mybots` → выбрать бота → **Edit Bot**:
- **Edit Name** → `Naomi Tours`;
- **Edit About** (до 120 символов, видно в профиле) → текст `BOT_SHORT_DESCRIPTION` из `profile.py`;
- **Edit Description** (экран до нажатия «Start», до 512 символов) → текст `BOT_DESCRIPTION`;
- **Edit Description Picture** → `design/bot/description.jpg` (640×360);
- **Edit Botpic** → `design/bot/avatar-navy.png` или `design/bot/avatar-orange.png` (640×640);
- **Edit Commands** → две строки: `start - Главное меню` и `cancel - Отменить заявку`.

Картинки пересоздаются командой `python design/make_bot_images.py`.

**Username бота у BotFather изменить нельзя** — для нового адреса (например, `@NaomiToursBot`) создаётся новый бот: `/newbot` → имя `Naomi Tours` → username. Затем:
1. В `.env` замените `BOT_TOKEN` и `BOT_USERNAME` на данные нового бота.
2. Оформите профиль нового бота (см. выше).
3. Пересоберите и опубликуйте сайт — иначе кнопки «Оставить заявку» поведут на старого бота:
   ```powershell
   python -m app.export_static --out docs --base-path naomi-tours-demo
   ```
4. Перезапустите `python -m app.bot`.

## Где смотреть заявки
Заявки хранятся в `data/naomi_tours_demo.db` (таблица `applications`, поле `tour_id` ссылается на `tours.id`).
1. Откройте **DB Browser for SQLite** → **Open Database** → `data/naomi_tours_demo.db`.
2. Вкладка **Execute SQL**:
   ```sql
   SELECT a.id, a.created_at, t.title, a.name, a.comment, a.telegram_username
   FROM applications a JOIN tours t ON t.id = a.tour_id ORDER BY a.id DESC;
   ```
Чтобы получать заявки сразу в Telegram, укажите свой числовой ID в `ADMIN_CHAT_ID` (узнать его можно, например, у @userinfobot) и перезапустите бота.

## Показ с телефона
Локальный сайт (`http://127.0.0.1:8000`) с телефона не открывается, поэтому для показа нужен публичный адрес.

**Вариант 1 — GitHub Pages (бесплатно, статическая копия сайта).** Сайт только показывает туры, а заявки принимает бот, поэтому статической копии достаточно.
```powershell
python -m app.export_static --out docs --base-path /<repo>
```
Затем закоммитьте папку `docs/`. В настройках репозитория: **Settings → Pages → Deploy from a branch → `main` / `/docs`**. Сайт будет доступен по адресу `https://<github-user>.github.io/<repo>/`.
В `.env` укажите `SITE_BASE_URL=https://<github-user>.github.io/<repo>` и перезапустите бота: ссылки из бота поведут на опубликованный сайт.
Каталог в статической копии фиксируется на дату сборки — после изменения туров или прошествия дат пересоберите `docs/`.

**Вариант 2 — живой сайт через туннель** (например, Cloudflare Tunnel или ngrok): запустите сайт локально, откройте туннель на порт 8000 и укажите выданный адрес в `SITE_BASE_URL`. Адрес туннеля меняется при каждом запуске, если не настроен постоянный.

В любом случае бот (`python -m app.bot`) должен быть запущен на компьютере — GitHub Pages его не запускает.

## Админ-панель и демо-группа (Этап 3)
Адрес на сервере: `https://geranium-unsavory-fiscally.ngrok-free.dev/naomi/admin`. Локально — `http://127.0.0.1:8000/admin`. Вход по паролю `ADMIN_PASSWORD` из `.env`; без пароля админка выключена. При первом входе из браузера бесплатный ngrok показывает своё предупреждение — нажмите **Visit Site** (один раз на браузер).

- **Заявки** — «Одобрить»: бот присылает человеку личную ссылку в группу. Ссылка «с одобрением»: бот впускает только людей с одобренной заявкой, посторонний по пересланной ссылке не попадёт. «Отклонить» — человеку уходит короткое нейтральное сообщение.
- **Туры** — «Добавить тур» / «Изменить». Новый тур сразу виден в боте, в группе появляется его тема и анонс с кнопкой «Оставить заявку», сайт на GitHub Pages обновляется примерно через минуту. Туры, изменённые в админке, при перезапуске не перезаписываются из `data/seed_tours.json`.

**Подключение группы (один раз):**
1. Создайте группу в Telegram и в её настройках включите **«Темы»**.
2. Добавьте @NaomiToursBot администратором с правами «Управление темами» и «Пригласительные ссылки».
3. Откройте админку → «Заявки» → **«Подключить»**. У каждого актуального тура появится своя тема.

ID группы вводить не нужно: бот замечает, что его добавили, а владелец подтверждает в админке. Бот отвечает только в личных сообщениях, в группе не пишет ничего, кроме анонсов.

## Сервер
Админка и бот работают в Docker на сервере владельца (`ps-server@192.168.2.38`, папка `~/naomi-tours`):
`web` (сайт + админка, `172.17.0.1:8095`, снаружи — через общий шлюз Travel Explorer по пути `/naomi/`) и `bot`. База — `~/naomi-tours/db/naomi_tours.db`, загруженные фото — `~/naomi-tours/uploads/`, клон сайта для автопубликации — `~/naomi-tours/site-repo` (ключ развёртывания с правом записи только в `naomi-tours-demo` — `~/naomi-tours/keys/`).

Обновление кода с Windows-компьютера:
```powershell
git archive --format=tar HEAD Dockerfile docker-compose.yml .dockerignore requirements.txt app data/seed_tours.json | ssh ps-server@192.168.2.38 "cd ~/naomi-tours && tar -xf - && docker compose up -d --build"
```
Логи: `ssh ps-server@192.168.2.38 "cd ~/naomi-tours && docker compose logs --tail 50 bot web"`.

**Бот должен работать только в одном месте.** Пока работает серверный бот, не запускайте `python -m app.bot` локально — Telegram не даст двум копиям получать сообщения одновременно.

Шлюз: блок `location /naomi/` в `~/travel-explorer/deploy/gateway-ngrok.conf` (копия до правки — `gateway-ngrok.conf.bak-naomi-*`).

## Тесты
```powershell
python -m pytest -q
```
Этап 3 (`tests/test_admin.py`): вход и защита от перебора, подделка cookie, подключение группы (в том числе без «Тем»), одобрение с приглашением, отклонение, добавление и изменение тура, загрузка фото, вступление в группу только с одобренной заявкой, автопубликация в git.
Покрыто: загрузка seed, уникальность и формат `tour_code`, скрытие завершившихся туров без удаления из БД, страницы сайта и 404, генерация start-ссылки, `/start` без аргумента / с валидным / неизвестным / завершившимся кодом, полный сценарий заявки с сохранением правильного `tour_id`, валидация имени, отмена, уведомление администратора. Бот тестируется вызовом хендлеров с фейковыми объектами, без обращения к Telegram.

## Правила данных
- Публичны туры, которые ещё не начались (`start_date > сегодня`); остальные скрыты из каталога, недоступны по прямой ссылке и в боте, но остаются в БД (пример — `burgundy_2026_11`).
- `"listed": false` в seed убирает тур из каталога и с главной, но страница и бот по прямой ссылке работают (так сейчас скрыт Лиссабон — программа и даты не подтверждены).
- Даты хранятся как ISO `DATE`. Поле `dates_are_demo=true` помечает условные демонстрационные даты — на сайте и в боте они подписаны «условные даты».
- Даты Грузии (20–27 марта 2027) — из исходного материала. Остальные даты 2027 года — условные.
- В seed можно унаследовать содержимое другого тура через `copy_from` (используется для Бургундии 2027).
- Платёжные реквизиты, PayPal, email для оплаты, списки участников и персональные данные из скриншотов не используются.

## Not in scope
Онлайн-оплата и PayPal/банк, сверка платежей, CRM, роли и личные кабинеты, рассылки, подключение к существующей группе Ирины, автоматическое добавление людей в группу (только сами по личной ссылке), отдельные группы на каждый тур, проверка свободных мест, Redis/очереди.
