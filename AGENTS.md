# AGENTS.md — постоянные инструкции Claude

## 1. Контекст
Проект Naomi Tours Demo создаётся полностью с нуля. В начале нет готового сайта, бота, БД, компонентов или структуры. Не предполагай, что что-либо уже существует. Это компактный внутренний демонстрационный прототип, а не коммерческая платформа.

## 2. Главный принцип
Сделай минимально сложное, но законченное решение. Предпочтительный стек: FastAPI + Jinja2 + HTML/CSS/минимальный JS + SQLite + aiogram 3.

Не использовать без объективной необходимости:
- React/Vue, микросервисы, Kubernetes, Redis, Celery;
- сложную инфраструктуру, очереди, универсальные абстракции;
- полноценную CRM или личные кабинеты (простая админ-панель Этапа 3 согласована владельцем 22.11.2026);
- дополнительные этапы сверх двух в ROADMAP.

## 3. Порядок работы
1. Прочитай README.md, ROADMAP.md и CONTENT_GUIDE.md.
2. Создай проектную структуру с нуля.
3. Реализуй оба этапа ROADMAP, не останавливайся на каркасе.
4. Запусти сайт, бота и тесты настолько, насколько позволяет конфигурация.
5. Обнови README фактическими командами.
6. В конце дай краткий отчёт: сделано, проверено, запуск, переменные окружения, оставшиеся реальные проблемы.

Не спрашивай пользователя о каждой мелочи. Принимай простые обратимые решения самостоятельно. Если есть настоящий блокер, назови его конкретно и объясни, что требуется.

## 4. Качество кода
- Понятные имена, небольшие функции, отсутствие дублирования.
- Разделять роуты, модели, сервисы и бота в разумных пределах.
- Добавить `.env.example`, `.gitignore`, `requirements.txt`.
- Не хранить секреты в коде.
- Даты хранить однозначно (ISO) и сравнивать корректно.
- Обрабатывать ошибки ввода и отсутствующие данные.
- Не оставлять заглушки вместо функций из ROADMAP.
- Не подавлять исключения пустым `except`.
- Не заявлять о проверках, которые не выполнялись.

## 5. Дизайн и изображения
Ориентир — скриншоты карточек и фотографии, переданные пользователем. Сохраняй общий характер карточек, содержание и исходные изображения. Приоритет — аккуратный мобильный вид.
- Не заменять исходные фотографии случайными стоками или генерацией.
- Если фото нельзя извлечь или сопоставить, использовать нейтральный плейсхолдер и сообщить об этом.
- Не добавлять тяжёлые библиотеки и анимации без необходимости.

## 6. Контент
- Исходные текст и скриншоты — источник содержимого.
- Не придумывать цены, услуги, даты перелётов, расписание, условия страховки/оплаты или детали маршрута.
- Если есть конфликт версий, использовать более позднюю информацию, как указал пользователь.
- Неизвестные факты не исправлять наугад.
- Грузия: 20–27 марта 2027 — дата из предоставленного материала.
- Для остальных туров даты 2027 года могут быть условными демонстрационными. Не выдавать их за подтверждённые Ириной отправления.
- Не показывать завершившиеся туры в публичном каталоге, но не удалять их из БД.
- Не использовать реальные реквизиты, платёжные адреса, персональные данные клиентов или списки участников.

## 7. Сайт
- Главная и каталог туров.
- Каждая карточка ведёт на отдельную страницу.
- Страница содержит кнопку «Оставить заявку».
- Каждому туру назначить стабильный уникальный `tour_code`.
- Ссылка вида `https://t.me/<BOT_USERNAME>?start=<tour_code>`.
- Завершившиеся туры исключать из публичной выдачи.
- Не обещать наличие места, если система его не проверяет.

## 8. Telegram
- `/start` без параметра: объяснить, что тур выбирают на сайте, дать ссылку.
- `/start <tour_code>`: найти нужный тур и показать его краткую информацию.
- Неизвестный код/завершившийся тур: объяснить и предложить каталог.
- Пользователь не вводит код вручную.
- Заявка — только запрос на рассмотрение, не подтверждённое бронирование.
- Не добавлять людей в группы и не подключаться к существующей группе Ирины.
- Уведомлять `ADMIN_CHAT_ID` только если он явно задан в `.env`.
- Даже без `ADMIN_CHAT_ID` сохранять заявку в SQLite.

## 9. Приватность и безопасность
- Только тестовые данные.
- Не собирать паспортные, банковские, платёжные данные, дату рождения и другие чувствительные сведения.
- Для демо достаточно имени, Telegram username/user ID (если доступен) и необязательного комментария.
- Не логировать токены и приватные данные.
- `.env` и локальную БД исключить из Git.
- Не подключать оплату и не отправлять реальные клиентские сообщения.

## 10. Минимальные проверки
Проверить:
- запуск сайта;
- карточки и страницы туров;
- скрытие завершившихся туров;
- генерацию start-ссылки;
- `/start` без аргумента;
- валидный/невалидный tour_code;
- сохранение заявки с правильным ID тура.

## 11. Не делать
Не делать полноценную CRM, оплату, электронные билеты, автоматическую сверку переводов, клиентские аккаунты, массовые рассылки, интеграцию с существующей группой Ирины, сложные роли и права. Админка и демо-группа — только в рамках Этапа 3 (ROADMAP): одна роль администратора, вход по паролю, люди попадают в группу только сами по личной ссылке после одобрения заявки. Не выдумывать содержание туров. Не растягивать работу больше чем на два этапа без технической причины.
