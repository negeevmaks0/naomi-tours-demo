# ROADMAP — два этапа

Проект создаётся с нуля. Не дробить работу на длинную последовательность формальных этапов.

## Этап 1 — сайт и наполнение
- [ ] Создать структуру Python-проекта.
- [ ] Настроить FastAPI, Jinja2, SQLite.
- [ ] Подготовить модель тура и демонстрационные данные.
- [ ] Создать главную страницу и каталог.
- [ ] Создать несколько карточек с исходными фотографиями.
- [ ] Создать отдельную страницу каждого тура.
- [ ] Отобразить описание, маршрут, программу, цену, включённое и дополнительные расходы, если они есть в источнике.
- [ ] Скрывать завершившиеся туры из публичного каталога.
- [ ] Сделать адаптивный мобильный интерфейс.
- [ ] Добавить каждой поездке уникальный `tour_code` и ссылку `https://t.me/<BOT_USERNAME>?start=<tour_code>`.
- [ ] Условные даты явно обозначить демонстрационными.
- [ ] Проверить сайт и ссылки.

**Результат:** работающий сайт с карточками, страницами туров и подготовленными ссылками на бота.

## Этап 2 — Telegram и заявки
- [ ] Подключить aiogram 3.
- [ ] `/start` без аргумента: сообщение о каталоге и ссылка на сайт.
- [ ] `/start <tour_code>`: найти тур и показать его информацию.
- [ ] Неизвестный код/завершившийся тур: корректное сообщение и ссылка на каталог.
- [ ] Реализовать простой сбор тестовой заявки.
- [ ] Сохранить заявку в SQLite с привязкой к туру.
- [ ] Если задан `ADMIN_CHAT_ID`, отправлять уведомление администратору; иначе только сохранять.
- [ ] Добавить отмену сценария и базовую валидацию.
- [ ] Написать тесты deep link/поиска тура/сохранения заявки.
- [ ] Обновить README фактическими командами запуска.
- [ ] Проверить полный путь сайт → бот → заявка.

Не начинать дополнительные функции, пока этот путь не работает. Всё вне объёма перечислить как `Not in scope`, не реализовывать самостоятельно.
